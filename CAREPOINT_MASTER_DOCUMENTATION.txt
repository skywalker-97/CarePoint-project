1. PROJECT OVERVIEW
------------------
* Project Kya Hai: 
  CarePoint ek advanced MERN stack healthcare platform hai. Ye sirf ek doctor booking site nahi hai, balki ek "AI-Powered Smart Clinic" hai jahan AI patient ki help karta hai sahi doctor dhundhne mein aur doctors ki help karta hai medical assessments mein.

* Problem Statement: 
  Existing systems mein patient ko pata nahi hota ki use kis specialist ki zarurat hai. Wo galat doctor book kar leta hai. Saath hi, doctors ko patient ki history manual check karni padti hai jo time-consuming hai.

* Purpose & Solution: 
  Is project ka main aim hai healthcare accessibility ko smart banana. Hamara system AI use karta hai "Emergency Risk" detect karne ke liye. Agar kisi ko heart attack ke symptoms hain, toh AI use turant hospital jane ki advice deta hai, na ki wait karne ki.

* Real-World Use Case: 
  Remote areas jahan turant doctor available nahi hote, wahan ye AI triage system life-saving ho sakta hai.

2. COMPLETE TECH STACK EXPLANATION
---------------------------------
* MongoDB (NoSQL): Database jahan hamara saara flexible data (Users, Doctors, Appointments) save hota hai.
* Express.js: Node.js ka framework jo API routing aur middle-ware management handle karta hai.
* React.js: Frontend library jo user-interface ko responsive aur dynamic banati hai (Vite tool use hua hai).
* Node.js: Backend runtime environment jo JavaScript ko server-side pe run karta hai.
* JWT (JSON Web Token): Secure Authentication ke liye. Bina token ke koi bhi sensitive API (jaise profile update) access nahi kar sakta.
* Socket.io: Real-time features ke liye. Jaise ki instant notifications aur live chat.
* Gemini AI (Google): Ye is project ka "Brains" hai. Ye symptoms analyze karta hai, specialist recommend karta hai, aur doctor ke notes se professional prescription draft karta hai.
* PDFKit: Digital prescriptions ko PDF format mein download karne ke liye.

3. FULL PROJECT WORKFLOW
-----------------------
* Patient Flow: 
  Register -> Login -> AI Symptom Check (AI recommends specialist) -> Select Doctor -> Select Slot -> Book -> Pay (Simulation) -> Real-time Chat with Doctor -> Get Digital Prescription.

* Doctor Flow: 
  Login -> Dashboard (Revenue & Stats) -> View Appointments -> Chat with Patient -> Access Patient History (AI Summarized) -> Complete Appointment -> Generate Prescription (AI Assisted).

* Admin Flow: 
  Dashboard Overview -> Doctor Verification -> Manage Specialties -> Monitor Revenue Intelligence (AI Predictions).

4. FOLDER STRUCTURE (IMPORTANT FOR VIVA)
----------------------------------------
* Backend:
  /config: Database aur Cloud services (Nodemailer) ki settings.
  /controllers: Saari logical coding (Logic layer).
  /models: Database schemas (Data layer).
  /routes: API endpoints definition.
  /utils: Helper functions (Socket initialization, Notify utility).
  /middleware: Security checks (authAdmin, authUser, authDoctor).

* Frontend:
  /src/assets: Images aur icons.
  /src/components: Reusable UI elements (Navbar, Footer, Modal).
  /src/context: Global states (AppContext, AdminContext, DoctorContext).
  /src/pages: Main screens (Home, Appointments, Dashboard).

5. DATABASE SCHEMA (COLLECTIONS)
-------------------------------
* User: Name, Email, Password (hashed), Image, Address, Medical History.
* Doctor: Name, Speciality, Degree, Fees, Experience, Slots_Booked (Object), IsVerified.
* Appointment: userId, docId, slotDate, slotTime, amount, status (cancelled/completed/payment).
* Prescription: diagnosis, symptoms, medicines array (medicine, dosage, duration), followUpPlan.
* Notification: userId, message, type (success/alert), isRead.
* Message: senderId, receiverId, messageContent, timestamp.

6. AUTHENTICATION & SECURITY
---------------------------
* Password Hashing: Humne 'Bcrypt.js' use kiya hai taaki agar database hack bhi ho jaye, toh koi passwords na padh sake.
* Protected Routes: React Router mein hum check karte hain "if (!token) redirect to login".
* Role-Based Access: Admin sirf admin portal dekh sakta hai, doctor sirf doctor portal. 

7. REAL-TIME FEATURES (SOCKET.IO)
--------------------------------
* Live Notifications: Jab doctor appointment complete karta hai, patient ko instant dashboard pe notification milta hai bina page refresh kiye.
* Socket Rooms: Humne unique rooms banaye hain based on UserIDs taaki messages sirf sahi person ko jayein.

8. AI FEATURES (THE INNOVATION)
------------------------------
* Emergency Escalation: AI prompt mein "isEmergency" flag set hai. Agar symptoms serious hain, toh flag TRUE ho jata hai.
* Clinical Assistant: Doctor rough notes likhta hai (e.g. "fever 102, headache"), AI use professional diagnosis mein convert kar deta hai.
* Revenue Intelligence: AI admin ko batata hai ki next month kitne patients aa sakte hain aur kitni revenue ho sakti hai based on history.

9. COMMON ERRORS + FIXES
------------------------
* CORS Issue: Backend allow nahi kar raha tha frontend URL ko. Fix: 'cors' package mein dynamic origin handling lagayi.
* 404 on Refresh: Render pe SPA routing issue. Fix: '_redirects' file banayi (/* /index.html 200).
* Mongoose URI Error: Env variable missing tha. Fix: Render dashboard mein manual variables add kiye.

10. DEPLOYMENT
--------------
* Frontend: Render Static Site (dist folder).
* Backend: Render Web Service (node server.js).
* Database: MongoDB Atlas (Shared Cluster).

11. VIVA QUESTIONS (PREPARATION)
-------------------------------
Q1: MERN stack kyun use kiya?
A: JavaScript-only tech stack hai, fast hai, aur scalable hai JSON-based data handle karne ke liye.

Q2: JWT aur Session mein kya fark hai?
A: JWT stateless hai, ye server ki memory consume nahi karta, token client-side pe save hota hai.

Q3: Socket.io kaise kaam karta hai?
A: Ye HTTP request-response cycle ke bajaye "WebSockets" use karta hai for full-duplex communication.

Q4: AI model konsa hai?
A: Google Gemini 1.5/2.0 Flash (latest models).

Q5: Database mein relationships kaise handle ki?
A: Reference IDs use kiye hain (ObjectId) jaise Appointment model mein user._id store kiya hai.
